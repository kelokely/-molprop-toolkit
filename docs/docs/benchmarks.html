Campaign workflow benchmark recipe

The campaign-level workflow checks are meant to run on a local paired-round dataset rather than a bundled public pack. The goal is to exercise integration, comparison, decision outputs, and handoff artifacts on data you are comfortable sharing inside your team.

What it runs

molscope integrate reference_round.csv assays_reference.csv -o reference_round_integrated.csv
molscope integrate candidate_round.csv assays_candidate.csv -o candidate_round_integrated.csv
molscope compare
molscope report
molscope picklists --html
molscope sar
molscope mmp
molscope learnings
molscope dashboard
molscope portal

What this checks

  • Measured assay joins stay reusable across downstream workflows.
  • Compare outputs surface both improvements and regressions.
  • Low-coverage measured endpoints remain visible as open questions.
  • Learnings, dashboard, and portal can assemble one review-ready evidence trail.
Observed signal in your paired-round run Expected artifact behavior
Measured microsomal stability improves across shared compounds in round 5. molscope compare and molscope learnings should promote that as a positive shift.
Measured solubility regresses across shared compounds. The round-review summary should keep a regression visible instead of only highlighting wins.
Measured_Caco2_AtoB is only available on one shared pair. The round-review summary should emit a low-coverage warning and an open question.
Scaffold_ID = SCF_C expands from round 4 to round 5. Group-delta outputs and learnings should flag that branch as a follow-up question, not just a count change.
Current benchmark baseline: workflow reliability and decision-support coherence are benchmarked more concretely than property-family calibration. That is intentional and should stay visible.
