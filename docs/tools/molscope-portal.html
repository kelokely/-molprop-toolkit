Campaign portal

Assemble previously generated report, picklist, compare, learnings, dashboard, SAR, MMP, and retrosynthesis bundles into one linked workspace with a single index.html entry point. This is the handoff layer for project reviews, collaborator shares, and static campaign snapshots.

Command: molscope portal.

Typical usage

molscope portal --report-dir reports/demo \
  --picklists-dir picklists/demo \
  --compare-dir compare/demo \
  --learnings-dir learnings/demo \
  --dashboard-dir dashboard/campaign_alpha \
  -o portal/demo

What you get

A static folder with a top-level index.html, copied sub-bundles for each supplied artifact directory, and metadata describing which sections were assembled.

Build a review-ready workspace

molscope report campaign.csv --outdir reports/round5
molscope picklists campaign.csv --outdir picklists/round5 --html
molscope learnings --picklists-dir picklists/round5 -o learnings/round5
molscope dashboard --learnings-dir learnings/round5 -o dashboard/campaign_alpha
molscope sar campaign.csv -o sar/round5
molscope mmp campaign.csv -o mmp/round5
molscope portal \
  --report-dir reports/round5 \
  --picklists-dir picklists/round5 \
  --learnings-dir learnings/round5 \
  --dashboard-dir dashboard/campaign_alpha \
  --sar-dir sar/round5 \
  --mmp-dir mmp/round5 \
  -o portal/round5

The portal command does not rerun those analyses. It assembles the outputs you already created and gives project teams one browseable starting point, including the persistent dashboard that carries lessons forward across rounds.

Why it matters

molscope portal is the bridge from generated artifacts to a campaign-facing workspace. Instead of shipping several folders and asking collaborators where to start, you hand them one linked bundle with direct paths into report, picklist, compare, learnings, dashboard, SAR, MMP, and retrosynthesis evidence.
